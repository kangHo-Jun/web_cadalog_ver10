# 가상서버 설치 및 Nginx 연결 가이드

## 1. 목적

이 문서는 초보자가 가상서버를 처음 설치하고, 웹사이트가 브라우저에서 정상적으로 열릴 때까지 진행하는 과정을 정리한 가이드이다.

현재 목표는 다음과 같다.

```text
가상서버 접속
→ Nginx 설치 및 실행
→ 80포트 확인
→ 브라우저에서 서버 IP 접속
→ 기본 페이지 확인
→ 사용자 index.html 출력 확인
```

---

## 2. 현재 완료된 서버 정보

현재 테스트한 서버 IP:

```text
115.68.228.60
```

브라우저 접속 주소:

```text
http://115.68.228.60
```

현재 확인 완료 상태:

```text
1. 서버 접속 정상
2. Nginx 설치 정상
3. Nginx 실행 정상
4. 80포트 열림
5. 브라우저에서 Nginx 기본 페이지 확인
6. /var/www/html/index.html 교체 후 사용자 테스트 페이지 출력 확인
```

---

## 3. 서버 접속

로컬 컴퓨터에서 SSH로 서버에 접속한다.

```bash
ssh root@115.68.228.60
```

정상 접속되면 프롬프트가 아래와 비슷하게 표시된다.

```bash
root@서버이름:~#
```

예:

```bash
root@daesan3833-309875:~#
```

---

## 4. Nginx 설치

서버에 Nginx가 설치되어 있지 않다면 아래 명령어를 실행한다.

```bash
apt update
apt install nginx -y
```

설치 후 Nginx 상태를 확인한다.

```bash
systemctl status nginx
```

정상이라면 `active (running)` 상태가 보여야 한다.

```text
Active: active (running)
```

---

## 5. Nginx 실행 및 재시작 명령어

Nginx 시작:

```bash
systemctl start nginx
```

Nginx 재시작:

```bash
systemctl restart nginx
```

Nginx 중지:

```bash
systemctl stop nginx
```

Nginx 자동 실행 등록:

```bash
systemctl enable nginx
```

Nginx 상태 확인:

```bash
systemctl status nginx
```

---

## 6. 80포트 확인

웹사이트는 기본적으로 80포트를 사용한다.

아래 명령어로 80포트가 열려 있는지 확인한다.

```bash
ss -tlnp | grep ':80'
```

정상 결과 예시:

```bash
LISTEN 0 511 0.0.0.0:80 0.0.0.0:* users:(("nginx",pid=1251,fd=6),("nginx",pid=1250,fd=6))
```

이 결과가 보이면 Nginx가 80포트에서 대기 중이라는 뜻이다.

---

## 7. 서버 내부에서 HTTP 응답 확인

브라우저 접속 전에 서버에서 직접 HTTP 응답을 확인한다.

```bash
curl -I http://115.68.228.60
```

정상 결과 예시:

```bash
HTTP/1.1 200 OK
Server: nginx/1.18.0 (Ubuntu)
Date: Mon, 01 Jun 2026 04:46:41 GMT
Content-Type: text/html
Content-Length: 612
Connection: keep-alive
```

중요한 부분:

```text
HTTP/1.1 200 OK
Server: nginx
```

이 결과가 나오면 웹서버가 정상 응답 중이다.

---

## 8. 브라우저에서 기본 페이지 확인

브라우저에서 아래 주소로 접속한다.

```text
http://115.68.228.60
```

처음에는 아래 문구가 보일 수 있다.

```text
Welcome to nginx!
If you see this page, the nginx web server is successfully installed and working.
```

이 화면은 오류가 아니다.

이 화면은 Nginx가 정상 설치되었고, 아직 실제 사이트 파일을 올리지 않았다는 의미이다.

---

## 9. Nginx 기본 웹 폴더 확인

Nginx의 기본 웹 폴더는 아래 경로이다.

```bash
/var/www/html
```

폴더 안의 파일을 확인한다.

```bash
ls -al /var/www/html
```

현재 확인된 결과:

```bash
drwxr-xr-x 2 root root 4096 Jun  1 13:37 .
drwxr-xr-x 3 root root 4096 Jun  1 13:36 ..
-rw-r--r-- 1 root root  612 Jun  1 13:37 index.nginx-debian.html
```

이 상태는 Nginx 기본 파일만 있는 상태이다.

```text
index.nginx-debian.html
```

이 파일 때문에 브라우저에 `Welcome to nginx!`가 표시된다.

---

## 10. 사용자 index.html 테스트 파일 만들기

실제 사이트를 올리기 전에, Nginx가 우리가 만든 파일을 제대로 보여주는지 테스트한다.

아래 명령어를 그대로 실행한다.

```bash
cat > /var/www/html/index.html <<'EOF'
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>Wang Yeul Test</title>
</head>
<body>
  <h1>Wang Yeul Site Test</h1>
  <p>Nginx is serving our custom index.html.</p>
</body>
</html>
EOF
```

파일 생성 후 다시 확인한다.

```bash
ls -al /var/www/html
```

정상이라면 아래처럼 `index.html`이 추가되어 있어야 한다.

```text
index.html
index.nginx-debian.html
```

---

## 11. 브라우저에서 사용자 테스트 페이지 확인

브라우저에서 다시 접속한다.

```text
http://115.68.228.60
```

정상이라면 기존의 `Welcome to nginx!`가 아니라 아래 문구가 보여야 한다.

```text
Wang Yeul Site Test
Nginx is serving our custom index.html.
```

이 화면이 보이면 성공이다.

즉, Nginx가 기본 페이지가 아니라 우리가 만든 `/var/www/html/index.html` 파일을 정상적으로 서비스하고 있다는 뜻이다.

---

## 12. 현재 단계의 의미

현재 단계까지 완료되었다면 다음이 확인된 것이다.

```text
서버 IP 접속 가능
Nginx 정상 실행
80포트 정상 연결
웹 브라우저 접근 가능
/var/www/html/index.html 출력 가능
```

따라서 이제 실제 웹사이트 파일을 `/var/www/html`에 올리면 된다.

## 13. 다음 단계: 실제 사이트 파일 업로드

```text
index.html
```


```text
/var/www/html

```

## 14. GitHub 방식으로 배포할 경우

사이트 코드가 GitHub에 있다면 서버에서 `git clone` 방식으로 가져올 수 있다.

먼저 git 설치 여부를 확인한다.

```bash
git --version
```

git이 없다면 설치한다.

```bash
apt update
apt install git -y
```

GitHub 저장소를 임시 폴더에 clone한다.

```bash
cd /tmp
git clone 저장소주소 wang-site
```

예시:

```bash
git clone https://github.com/계정명/저장소명.git wang-site
```

복사 전 기존 테스트 파일을 백업한다.

```bash
cp -r /var/www/html /var/www/html_backup
```

기존 파일 삭제:

```bash
rm -rf /var/www/html/*
```

새 사이트 파일 복사:

```bash
cp -r /tmp/wang-site/* /var/www/html/
```

Nginx 재시작:

```bash
systemctl restart nginx
```

브라우저에서 확인:

```text
http://115.68.228.60
```

## 15. 로컬 파일을 직접 업로드할 경우

로컬 컴퓨터에서 `scp` 명령어를 사용할 수 있다.

예시:

```bash
scp -r ./사이트폴더/* root@115.68.228.60:/var/www/html/
```

업로드 후 서버에서 확인한다.

```bash
ls -al /var/www/html
```

Nginx 재시작:

```bash
systemctl restart nginx
```

브라우저에서 확인:

```text
http://115.68.228.60
```

# 문제 해결 가이드

## 16. 브라우저에 접속이 안 될 때

### 16.1 Nginx 상태 확인

```bash
systemctl status nginx
```

정상:

```text
active (running)
```

비정상이라면 재시작한다.

```bash
systemctl restart nginx
```

---

### 16.2 80포트 확인

```bash
ss -tlnp | grep ':80'
```

결과가 없다면 Nginx가 80포트를 사용하지 못하고 있는 것이다.

Nginx 재시작:

```bash
systemctl restart nginx
```

다시 확인:

```bash
ss -tlnp | grep ':80'
```

---

### 16.3 서버 응답 확인

```bash
curl -I http://115.68.228.60
```

정상:

```text
HTTP/1.1 200 OK
```

오류가 나면 Nginx 설정 또는 방화벽 문제일 가능성이 있다.

---

## 17. Welcome to nginx!가 계속 보일 때

원인:

```text
실제 사이트 파일이 아직 /var/www/html/index.html에 적용되지 않았거나,
브라우저 캐시가 남아 있을 수 있다.
```

확인:

```bash
ls -al /var/www/html
```

`index.html`이 있는지 확인한다.

```bash
cat /var/www/html/index.html
```

내용이 실제 사이트 파일인지 확인한다.

브라우저 강력 새로고침:

```text
Mac: Cmd + Shift + R
Windows: Ctrl + F5
```

---

## 18. 403 Forbidden이 나올 때

원인:

```text
index.html 파일이 없거나,
파일 권한 문제일 가능성이 높다.
```

확인:

```bash
ls -al /var/www/html
```

`index.html`이 없다면 생성하거나 업로드한다.

권한 수정:

```bash
chmod -R 755 /var/www/html
```

소유자 수정:

```bash
chown -R www-data:www-data /var/www/html
```

Nginx 재시작:

```bash
systemctl restart nginx
```

---

## 19. 404 Not Found가 나올 때

원인:

```text
요청한 파일이 /var/www/html 안에 없거나,
Nginx root 경로가 다를 수 있다.
```

확인:

```bash
ls -al /var/www/html
```

Nginx 설정 확인:

```bash
cat /etc/nginx/sites-available/default
```

아래 설정이 있는지 확인한다.

```nginx
root /var/www/html;
index index.html index.htm index.nginx-debian.html;
```

설정 수정 후에는 반드시 테스트한다.

```bash
nginx -t
```

정상이라면 재시작한다.

```bash
systemctl restart nginx
```

---

## 20. Nginx 설정 오류 확인

Nginx 설정이 맞는지 검사한다.

```bash
nginx -t
```

정상 결과:

```text
syntax is ok
test is successful
```

오류가 있으면 재시작하지 말고, 오류 메시지에 나온 파일과 줄 번호를 먼저 수정한다.

---

## 21. Nginx 로그 확인

접속 오류 로그 확인:

```bash
tail -n 50 /var/log/nginx/error.log
```

접속 기록 확인:

```bash
tail -n 50 /var/log/nginx/access.log
```

실시간 로그 확인:

```bash
tail -f /var/log/nginx/error.log
```

---

## 22. 방화벽 확인

Ubuntu 방화벽 상태 확인:

```bash
ufw status
```

비활성 상태라면:

```text
Status: inactive
```

활성 상태인데 80포트가 막혀 있다면 허용한다.

```bash
ufw allow 80
ufw allow 443
ufw reload
```

---

## 23. 서버 업체 방화벽 확인

서버 내부 설정이 정상인데도 외부 브라우저 접속이 안 된다면, 서버 업체의 보안그룹 또는 방화벽에서 80포트가 막혀 있을 수 있다.

확인할 항목:

```text
인바운드 80포트 허용
인바운드 443포트 허용
SSH 22포트 허용
```
